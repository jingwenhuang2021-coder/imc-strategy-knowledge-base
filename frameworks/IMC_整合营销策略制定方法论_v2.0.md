# IMC 整合营销策略与落地方法论 v2.0

> 版本：2.0  
> 更新日期：2026-10-25  
> 用途：从业务诊断、营销策略、渠道组合，到 campaign 执行、测量和优化的完整工作框架。  
> 使用原则：先明确业务问题和行为目标，再选择渠道；渠道清单不是策略本身。

---

## 0. v2.0 升级说明

v1.0 重点解决“如何诊断业务问题并形成传播策略”。v2.0 将框架扩展到完整 IMC 规划与执行，补齐 Paid Ads、PR、KOL/Creator、Social、CRM/EDM、Event、Retail、SEO/Search、Website/DTC、Partnership、Affiliate 等渠道的选择、分工、协同、预算和测量方法。

新版分为三个层次：

1. **Strategy：决定打什么仗。** 业务诊断、市场竞争、用户旅程、TA、Insight、价值主张和行为目标。
2. **IMC Planning：决定通过什么组合赢。** 渠道选择、渠道任务、内容与创意、媒体计划、预算、日历、执行机制。
3. **Measurement & Optimization：判断是否有效以及如何调整。** KPI、归因、增量测量、实验和复盘。

完整 IMC 不等于把所有渠道都做一遍。一个有效方案可以只选少数渠道，但必须解释每个渠道为什么存在、承担什么任务、与其他触点如何衔接，以及如何判断它是否有效。

## 1. Business & Market Diagnosis：业务与市场诊断

### 1.1 先定义业务问题

先写清楚：
- **业务目标：** 销售额、销量、市场份额、利润、新品渗透、线索、品牌认知或用户留存。
- **目标范围：** 国家/地区、产品线、渠道、人群、时间窗口。
- **基线与目标：** 当前值、目标值、完成期限、可接受成本。
- **业务约束：** 预算、库存、价格、供应、产品能力、渠道覆盖、法规、团队资源。
- **决策需求：** 这次分析最终要支持什么选择？

将“销量不好”改写成可诊断的问题，例如：“过去 6 周，西班牙 DTC 的产品页访问量相对稳定，但加购率低于法国和意大利；需要判断主要损失来自流量质量、产品价值理解、价格/信任障碍，还是转化体验。”

### 1.2 诊断漏斗：哪里发生损失

| 阶段 | 指标示例 | 常见问题 |
|---|---|---|
| Reach | 目标人群触达、有效频次、覆盖 | 覆盖不足、受众不准、频次过高 |
| Attention | 有效观看、CTR、互动、品牌搜索 | 创意不相关、钩子不足、信息不清 |
| Consideration | 产品页访问、停留、规格/FAQ 浏览 | 流量意图不匹配、产品理解困难 |
| Intent | 加购、咨询、预约、线索提交 | 价值感不足、顾虑未解决、CTA 不清 |
| Conversion | CVR、订单、CAC、线索转化率 | 价格、支付、库存、物流、销售跟进 |
| Retention/Advocacy | 复购、推荐、评价、UGC、退货率 | 体验落差、服务问题、缺少用户运营 |

不要单看总体数字。按国家、渠道、受众、创意、设备、落地页、价格/促销和时间段切分；确认样本量和统计口径是否可比。

### 1.3 诊断购买链路：为什么发生损失

梳理需求触发 → 品类认知 → 产品理解 → 方案评估 → 信任建立 → 购买行动 → 使用与口碑。

证据来源包括用户访谈、搜索词、评论、客服问题、退货原因、站内行为、销售反馈、零售观察、竞品内容与市场研究。区分**已知事实、推断、待验证假设**，不要把营销团队的直觉直接写成消费者洞察。

### 1.4 从症状到根因假设

建议每条假设写成：

> 观察到的异常 → 证据 → 可能机制 → 可干预变量 → 预期变化 → 验证方式

例：产品页访问稳定但加购率偏低 → 访谈中用户难以理解 8K/360 的实际使用价值 → 可能存在“技术参数与个人利益脱节” → 增加真实场景演示和使用案例 → 观察加购率及后续成交是否提升 → 通过 A/B 测试或分组对照验证。

**边界提醒：** 并非所有问题都能靠营销解决。价格、产品竞争力、库存、售后、物流、网站性能、销售跟进等问题需要与产品、电商、销售、客服和运营团队共同处理。

## 2. Market, Competitor & Category：市场、竞争与品类

至少分析四类替代方案：
1. 直接竞品；
2. 间接竞品或不同技术路线；
3. 用户当前正在使用的方案；
4. 用户“不买/继续等待”的选择。

竞品研究不要止于价格表，应比较：
- 目标人群与场景；
- 核心主张、产品利益和证据；
- 内容叙事与创意形式；
- 渠道组合与促销机制；
- 评价、口碑和常见顾虑；
- 产品页、零售体验、售后承诺；
- 可观察的优势、弱点与信息空白。

输出应回答：我们在哪个需求或场景中有机会赢？哪些主张已经同质化？我们需要证明什么，而不仅仅是宣称什么？

## 3. Target Audience & Consumer Insight：TA 与消费者洞察

### 3.1 TA 不只是人口统计

定义核心 TA 时，尽量包括：
- 需求/任务与使用场景；
- 当前解决方案与熟悉程度；
- 购买阶段及决策影响者；
- 关键购买标准；
- 主要障碍和触发事件；
- 媒体/内容习惯（有证据时再写）；
- 商业价值与可触达性。

### 3.2 洞察结构

可用以下句式形成初步假设：

> 我在【场景】下想要【目标】，但因为【障碍/矛盾】，所以我会【当前行为/犹豫】；如果有【可信证据/解决方式】，我才更愿意【目标行为】。

Insight 不是一句漂亮的广告文案。它应解释用户为什么在意、为什么犹豫，以及什么可能改变其行为。每条洞察应标注证据来源和置信度。

## 4. Brand & Communication Strategy：品牌与传播策略

### 4.1 策略逻辑链

**WHO**：为谁解决问题？  
**WHY**：用户为什么在意？关键障碍是什么？  
**WHAT**：我们提供什么价值？凭什么胜出？  
**CHANGE**：需要改变什么认知、态度或行为？  
**HOW**：用什么主张、创意、触点和证据实现改变？  
**PROOF**：什么数据能证明方案有效？

### 4.2 KSP → Benefit → Proof

不要只罗列产品参数。每个核心卖点应包含：
- 产品事实/KSP；
- 对用户的实际利益；
- 适用场景；
- 证明方式；
- 与竞品/替代方案的差异；
- 合规边界与不能夸大的表述。

### 4.3 设定行为目标

将模糊目标改成可观察行为：
- 从“不知道品类”到主动搜索；
- 从“知道产品”到理解核心差异；
- 从“感兴趣”到观看完整评测或访问产品页；
- 从“有疑虑”到预约体验、咨询或加入邮件列表；
- 从“考虑中”到加购/下单；
- 从“买过”到评价、推荐或创作 UGC。

## 5. Channel Strategy：渠道选择，不是渠道点名

### 5.1 渠道选择矩阵

对候选渠道逐一回答：

| 维度 | 要问的问题 |
|---|---|
| 目标匹配 | 它是否能推动当前阶段的目标？ |
| TA 匹配 | 目标人群是否在这里，且能否有效触达？ |
| 任务匹配 | 更适合建立认知、解释复杂信息、建立信任、促转化还是体验？ |
| 证据与内容匹配 | 该渠道的形式能否把关键价值讲清楚、证明出来？ |
| 转化承接 | 触达后用户下一步去哪？承接页面/销售/客服是否准备好？ |
| 成本与资源 | 费用、制作周期、人力和机会成本是否合理？ |
| 测量能力 | 能否衡量输出、行为和业务结果？ |
| 风险 | 平台依赖、品牌安全、法规、供应商和执行风险如何？ |

可用 1–5 分进行相对评分，但分数只是辅助决策；高分不能替代策略判断。对关键假设标明“事实/估计/待测试”。

### 5.2 渠道角色地图

| 渠道 | 常见强项 | 常见限制 | 更适合承担的任务 |
|---|---|---|---|
| Paid Ads（付费广告） | 可控触达、快速测试、可优化转化 | 预算消耗快、创意疲劳、归因偏差 | 放大已验证信息、捕获需求、再营销、测试 |
| PR / Earned Media | 第三方可信度、议题设置、声誉建设 | 发布时点和信息控制有限，曝光不等于转化 | 建立公信力、解释新品/技术、处理信任障碍 |
| KOL / Creator | 借助创作者语境解释产品、示范使用 | 受创作者匹配和内容质量影响 | 场景教育、真实体验、评测、社群影响 |
| Organic Social | 持续互动、品牌个性、内容沉淀 | 自然触达不稳定 | 日常沟通、UGC、社群关系、内容复用 |
| SEO / Search | 承接主动需求、长期搜索流量 | 建设周期较长，需持续优化 | 解决问题型搜索、品类教育、需求捕获 |
| CRM / EDM | 面向已知用户触达、生命周期运营 | 依赖名单质量、同意管理和内容相关性 | 培育线索、教育、促销、弃购挽回、留存 |
| Event / Experiential | 亲身体验、现场答疑、关系建立 | 成本和覆盖有限、执行复杂 | 降低体验不确定性、试用、线索获取、媒体关系 |
| Retail / Demo | 现场体验、销售人员解释、即时购买 | 受门店覆盖、人员和库存影响 | 产品演示、咨询、购买承接 |
| Website / DTC | 信息承接、转化、数据沉淀 | 页面和体验不佳会浪费上游流量 | 解释价值、比较、转化、售后与服务承诺 |
| Partnership / Affiliate | 借助合作伙伴资源或分销关系 | 合作质量和利益一致性不一 | 扩大场景覆盖、共享资源、引荐与销售 |
| Community / UGC | 用户信任、长期关系、真实使用案例 | 需要持续运营，不宜只靠短期激励 | 口碑、用户教育、推荐、内容资产积累 |

这张表是一般性判断，不是固定规则。某渠道的实际效果取决于目标人群、产品类别、市场、执行质量和预算。

## 6. Channel Orchestration：渠道之间如何协同

### 6.1 先定义触点任务，再定义渠道

每个渠道必须有一个明确的主要任务，并可有辅助任务。例如：
- PR：建立第三方可信度；
- YouTube 深度评测：解释复杂功能并提供证据；
- 短视频：激发兴趣、展示使用场景；
- Search：承接已经形成的主动需求；
- 产品页：比较方案、回答顾虑、推动转化；
- Event/Retail Demo：让用户亲身体验；
- EDM：根据用户阶段补充信息、推进下一步；
- Paid retargeting：提醒和回应特定未完成行为，而不是无差别重复广告。

### 6.2 设计用户路径

示例路径：

1. 用户通过短视频首次看见产品；
2. 对功能感兴趣，搜索品牌/品类；
3. 阅读专业评测或 PR 报道，建立初步信任；
4. 访问产品页，比较规格、价格和售后；
5. 仍不确定时，预约线下体验或查看真实用户案例；
6. 留下邮件后，收到与其兴趣相关的教育内容；
7. 完成购买后，进入新手引导、评价和推荐流程。

真实用户路径可能跳跃、重复或从线下开始。此路径是规划工具，不应当成所有人必经的线性漏斗。

### 6.3 统一与适配

统一的部分：
- 核心价值主张；
- 产品事实和合规边界；
- 视觉识别与品牌语气；
- 关键证明材料；
- 用户下一步行动。

需要适配的部分：
- 内容长度、叙事节奏和格式；
- 信息深度；
- 平台语境与受众心态；
- CTA 与落地页；
- 不同市场的语言、文化和购买障碍。

**IMC 的重点不是所有渠道发同一条内容，而是让所有渠道共同完成同一项业务任务。**

## 7. Content & Creative Strategy：内容与创意策略

### 7.1 建立内容支柱

建议每个 campaign 先定义 3–5 个内容支柱，具体数量按项目调整：
- **Problem/Need：** 需求触发与痛点；
- **Education：** 品类、功能、技术和使用方法；
- **Proof：** 测试、专业评测、真实案例、用户评价；
- **Use Cases：** 具体场景与生活方式；
- **Objection Handling：** 价格、安装、兼容、售后、风险；
- **Conversion：** 优惠、库存、购买理由、CTA；
- **Community/Advocacy：** 用户故事、UGC、推荐和长期关系。

### 7.2 每个内容 Brief 应包含

- 目标人群和购买阶段；
- 内容任务（要改变什么）；
- 单一核心信息；
- 需要呈现的用户利益和证明；
- 形式、平台与时长；
- 语气、视觉和必要素材；
- CTA 与目标落地页；
- KPI 与成功标准；
- 法务、品牌、产品事实和本地化审核要求。

不要让一条内容同时承担“建立品类认知、解释全部技术、回应售后顾虑、促销成交”所有任务。优先级越清楚，内容越容易有效。

## 8. Paid Media & Advertising：付费广告 Playbook

### 8.1 先决定广告的任务

常见任务：
- 品牌/品类认知；
- 需求捕获（Search）；
- 内容放大（Amplification）；
- 线索/预约；
- 电商转化；
- 再营销；
- 创意与受众测试。

不要把所有广告都用 ROAS 评价。上层漏斗广告应使用与其目标匹配的指标，并通过实验、品牌研究或增量分析理解其对业务的贡献。

### 8.2 广告规划流程

1. 定义业务目标、目标受众和目标行为；
2. 选择渠道、版位、受众和投放优化事件；
3. 设计创意假设与测试变量；
4. 建立预算、出价、频次和学习期管理规则；
5. 设置追踪、UTM、像素/转化 API（遵循同意与隐私要求）；
6. 确保广告与落地页信息一致；
7. 监控质量、成本、频次、转化和增量；
8. 根据数据迭代受众、创意、出价、落地页与预算。

### 8.3 创意测试建议

测试时一次优先改变少数关键变量，例如：
- 场景 vs 参数；
- 情绪利益 vs 功能利益；
- 创作者讲述 vs 产品演示；
- 社会证明 vs 直接主张；
- 不同钩子、首屏、CTA。

记录假设、样本量、测试窗口、主要指标和决策阈值。避免因样本太小、季节变化或促销差异过早下结论。

### 8.4 常用指标

- 触达：Reach、Impressions、Frequency、CPM；
- 注意力：有效观看、视频完成率、CTR；
- 访问：CPC、LPV、落地页访问率；
- 转化：CVR、CPA/CAC、ROAS；
- 增量：增量转化、增量收入、iROAS（在方法和数据条件允许时）。

注意：平台报告的归因转化不等于广告带来的全部增量转化；点击率高也不一定意味着高质量流量。

## 9. PR & Earned Media Playbook：公关与赢得媒体

### 9.1 PR 先确定沟通任务

可能的任务包括：
- 新品发布与品类教育；
- 建立第三方可信度；
- 技术、创新或品牌故事；
- 企业声誉与议题管理；
- 关键市场/行业影响力；
- 危机回应与事实澄清。

### 9.2 PR 规划流程

1. 明确新闻价值：为什么现在值得报道？
2. 定义目标媒体与记者类型：大众、科技、垂直、商业、生活方式或本地媒体；
3. 设计消息层级：核心信息、支撑事实、证据、品牌背景；
4. 准备新闻资料包：新闻稿、图片、产品事实表、FAQ、发言人、演示/评测资源；
5. 规划发布节奏：预热、发布、深度报道、后续案例；
6. 管理沟通：媒体定向、采访、样机、事实核对与跟进；
7. 记录报道质量、信息准确性、关键消息露出和后续影响。

### 9.3 PR 不应只看发布数量

建议评估：
- 目标媒体覆盖与报道质量；
- 关键消息是否准确出现；
- 第三方评价/可信度；
- 目标受众触达（可获取时）；
- Referral traffic、品牌搜索、线索或销售辅助信号；
- 声誉风险与错误信息处理。

AVE（广告价值等值）不宜单独作为 PR 价值的充分证明。PR 对销量的影响往往通过信任、搜索、评估和其他触点间接发生，需谨慎解释归因。

## 10. KOL & Creator Marketing Playbook

### 10.1 先按任务选创作者，而不是只按粉丝量

评估维度：
- 受众与核心 TA 匹配；
- 内容垂类与场景可信度；
- 叙事/演示能力；
- 受众互动质量；
- 过往内容表现和品牌安全；
- 报价、制作成本、授权和使用期限；
- 内容交付稳定性与合作风险。

### 10.2 常见创作者角色

- Reach creator：扩大覆盖；
- Educator/Reviewer：解释复杂功能、提供评测；
- Use-case creator：展示具体场景；
- Community creator：与垂直社群建立关系；
- Conversion creator：推动购买、优惠码或联盟转化。

同一位创作者可以承担多个角色，但 Brief、成功指标和内容预期应明确。

### 10.3 合作流程

目标与人群 → 创作者筛选 → 受众/内容审查 → Brief → 创作与审核 → 发布 → 放大授权 → 追踪 → 复盘与关系管理。

合同应明确交付件、发布时间、修改轮次、披露要求、广告授权、素材使用范围、期限、地域、竞品排他和付款节点。遵守当地广告披露法规与平台政策。

### 10.4 指标

有效观看、目标受众触达、互动质量、信息传达、品牌搜索/网站访问、优惠码/联盟转化、内容授权后表现、每次有效观看成本等。不要仅用总播放量评价所有创作者；不同角色应有不同 KPI。

---

## 11. CRM & EDM Playbook：邮件与生命周期营销

### 11.1 EDM 的价值

EDM 不只是促销群发。它适合向已知且合法可联系的用户持续提供相关信息，尤其在用户已经表达兴趣、留下线索或完成购买后。

### 11.2 常见自动化流程

| Flow | 触发条件 | 内容任务 |
|---|---|---|
| Welcome | 用户订阅/注册 | 介绍品牌价值、偏好与下一步 |
| Lead Nurture | 用户下载资料/预约/留资 | 逐步教育、案例、答疑 |
| Browse/Cart Abandonment | 浏览或加购未完成（按同意及技术条件） | 回应阻碍、补充信息、提醒行动 |
| Launch/Promotion | 新品/活动与目标人群相关 | 介绍价值、证据、优惠和期限 |
| Post-purchase | 完成购买 | 使用指南、设置、服务入口 |
| Review/Referral | 体验后适当时点 | 邀请评价、分享或推荐 |
| Win-back | 一段时间未活跃 | 相关新品、内容或偏好更新 |

### 11.3 EDM 规划要素

- 名单来源、同意状态和退订机制；
- 用户分群与生命周期阶段；
- 发送触发、频率和抑制规则；
- Subject line、Preheader、正文、CTA；
- 个性化逻辑与数据质量；
- 落地页和后续体验；
- 渲染、链接、移动端与可访问性 QA；
- 发送后监测与迭代。

### 11.4 指标与注意事项

关注送达率、退信、点击率、转化、退订、投诉、收入/线索及增量表现。打开率可能受隐私保护机制影响，不能单独当作用户真实阅读的可靠指标。遵守适用的隐私、同意、数据保留和电子营销法规；不要默认所有客户都可被营销邮件触达。

## 12. Event & Experiential Marketing Playbook：活动与体验营销

### 12.1 先确定活动要改变什么

活动适合的任务包括：
- 让用户亲身体验难以通过屏幕解释的产品；
- 降低性能/效果不确定性；
- 产生合格线索、预约或现场销售；
- 建立媒体、创作者、零售或合作伙伴关系；
- 形成可复用内容与社区关系。

如果活动目标只是“做曝光”，要先问：目标受众是谁？活动能提供什么线上内容无法提供的价值？如何承接后续行为？

### 12.2 活动类型与适用情境

- Trade show / Expo：行业影响力、线索、产品演示、合作伙伴；
- Media/KOL Preview：深度讲解、评测体验、关系建立；
- Retail Demo / Workshop：用户教育、试用、咨询和购买；
- Community Meetup：用户关系、UGC、推荐；
- Roadshow / Pop-up：多城市体验、市场教育；
- Webinar / Virtual Event：远程教育、线索培育；
- Brand Experience：沉浸式体验与品牌记忆。

### 12.3 活动策划流程

1. 定义目标、目标人群和成功标准；
2. 选择活动形式与城市/场地；
3. 设计体验机制与用户旅程；
4. 明确报名、邀约、提醒和现场动线；
5. 规划人员、设备、样机、供应商、物料和安全；
6. 设计 lead capture 与隐私告知；
7. 设置现场 CTA：预约、购买、扫码、订阅或咨询；
8. 规划内容采集、媒体/创作者安排与素材授权；
9. 制定风险预案：天气、设备、取消、人员、运输和替代方案；
10. 活动后及时跟进线索、内容发布和销售机会。

### 12.4 活动 KPI

- 报名数、到场率、目标人群占比；
- 体验人数、体验完成率、互动深度；
- 合格线索、预约、现场销售、后续成交；
- 单条合格线索成本、单次体验成本；
- 内容产出、媒体/创作者触达；
- 满意度、后续跟进率、机会转化；
- 成本与实际业务结果。

不要只汇报报名数或到场人数。建议区分报名、到场、体验、合格线索、成交等层级。活动 ROI 应说明成本范围、收入归属窗口和归因限制。

### 12.5 活动复盘模板

目标与假设 → 实际到场与目标人群 → 体验/线索/销售漏斗 → 成本明细 → 内容与媒体结果 → 线索跟进 → 发生的问题 → 可复用资产 → 下次继续/停止/调整的决策。

---

## 13. Retail, Partnership, Affiliate & Community

### Retail / Demo
重点考虑门店覆盖、店员培训、展示位置、体验流程、库存、促销、二维码/预约路径、销售线索回传。零售活动不应只看现场人流，也要看目标客群、体验质量和后续成交。

### Partnership / Co-marketing
先明确双方共同目标、受众互补性、资源投入、品牌安全、数据权限和交付责任。合作内容应让双方受众都获得真实价值，而不是简单并列 Logo。明确谁负责审批、执行、线索处理与复盘。

### Affiliate / Referral
明确佣金规则、归因窗口、优惠码冲突、退货扣回、作弊防范、披露要求和合作方质量。评估增量贡献，不应只把所有带码订单都视为新增订单。

### Community / UGC
建立从参与、创作、授权、发布到反馈的机制。明确用户授权、使用范围、隐私和激励规则。社区经营以长期价值为目标，避免只在新品发布时短暂出现。

---

## 14. Website, DTC, SEO & Conversion Enablement

上游传播必须有下游承接。检查：
- 广告/创作者/PR 的主张是否与落地页一致；
- 首屏是否快速回答“这是什么、适合谁、有什么价值”；
- 关键证据、规格、对比、FAQ 和真实案例是否容易找到；
- 价格、库存、配送、退换和售后信息是否清楚；
- 移动端性能、支付流程和本地化是否可靠；
- CTA 是否对应用户阶段；
- 表单是否过长、隐私说明是否清晰；
- 线索是否被及时分配并跟进。

SEO 内容应围绕真实搜索意图：品类解释、问题解答、比较、评测、使用指南和售后问题。SEO 与 Paid Search 可以互相提供关键词和需求洞察，但目标、成本结构与评估窗口不同，应分别测量。

## 15. Budget & Resource Allocation：预算与资源配置

### 15.1 先设预算逻辑

预算不应只按去年比例复制。建议综合考虑：
- 业务目标与所需增量；
- 用户旅程中的主要障碍；
- 渠道边际成本和预期贡献；
- 证据强度与不确定性；
- 制作、人力、活动、授权、技术和跟进成本；
- 测试预算与风险储备。

### 15.2 推荐的预算拆分方式

| 预算池 | 示例内容 |
|---|---|
| Paid media | 社媒广告、搜索广告、再营销 |
| Content production | 创意、视频、摄影、设计、本地化 |
| Creator / KOL | 合作费、制作费、授权和内容放大 |
| PR | 媒体活动、样机物流、新闻资料、供应商 |
| Event / Experience | 场地、搭建、设备、人员、物流、差旅 |
| CRM / Tech | 邮件平台、自动化、数据与追踪工具 |
| Retail / Partnership | 陈列、培训、联合传播、合作资源 |
| Measurement / Research | 用户研究、品牌研究、实验和数据分析 |
| Contingency | 应急与执行变更 |

### 15.3 资源分配原则

- 把钱投入到当前瓶颈，而不是平均分给渠道；
- 区分“已验证有效”“有潜力待验证”“暂不优先”；
- 为新渠道设置有限测试预算、时间窗口和停止条件；
- 把创意制作、授权、人员和线索跟进计入总成本；
- 对活动、PR、品牌广告等难以直接归因的项目，预先定义合理的中间指标与增量验证方式。

## 16. Campaign Calendar & Execution：活动日历与执行管理

### 16.1 从策略拆到工作流

典型阶段：
1. Strategy lock：目标、TA、主张、渠道角色、预算确认；
2. Briefing：创意、媒体、PR、Creator、活动和 CRM Brief；
3. Production：制作、翻译、本地化、法务/品牌审核；
4. QA：链接、UTM、落地页、库存、追踪、邮件渲染、现场演练；
5. Launch：发布、投放、活动执行、线索分配；
6. Optimization：监控、测试、预算和内容调整；
7. Follow-up：线索跟进、EDM 培育、内容复用；
8. Review：业务结果、增量证据、学习和下一轮决策。

### 16.2 Campaign calendar 必备字段

| 字段 | 说明 |
|---|---|
| Workstream / Channel | Paid、PR、Creator、EDM、Event、Web 等 |
| Deliverable | 具体交付物，不只写“社媒”或“PR” |
| Audience / Journey stage | 面向谁、处于什么阶段 |
| Message / CTA | 核心信息与下一步行动 |
| Owner / Approver | 执行负责人和审批人 |
| Start / Due / Go-live | 开始、截止和上线日期 |
| Dependencies | 产品信息、样机、素材、页面、库存等依赖 |
| Budget | 预算、供应商和采购状态 |
| KPI / Tracking | 成功标准、UTM、事件和数据来源 |
| Status / Risk | 进度、风险、备选方案 |

### 16.3 RACI 与治理

对关键交付物明确：
- **R — Responsible：** 实际执行者；
- **A — Accountable：** 最终负责/拍板者；
- **C — Consulted：** 需要征询意见者；
- **I — Informed：** 需要同步信息者。

关键项目只设一个明确的 A。跨团队协作中，提前确认产品、法务、销售、电商、客服、供应商和区域团队的责任边界及审批时限。

### 16.4 风险与依赖管理

建立风险清单：风险、发生概率、影响、预警信号、Owner、应对措施、备选方案。活动场地、创作者取消、样机延误、库存不足、页面未上线、追踪失效和当地合规问题都应提前考虑。

## 17. Measurement & Optimization：测量、归因与优化

### 17.1 KPI 三层结构

| 层级 | 示例 | 用途 |
|---|---|---|
| Output | 曝光、发布数量、到场人数、内容交付 | 确认执行是否完成 |
| Outcome | 有效观看、认知、搜索、访问、合格线索、加购 | 判断用户是否发生预期变化 |
| Business impact | 增量订单、收入、利润、CAC、留存 | 判断是否创造业务价值 |

每个项目应优先选择少数与目标直接相关的主 KPI，再设置必要的诊断指标。避免 KPI 太多导致团队无法判断优先级。

### 17.2 归因不是增量

- **平台归因：** 按平台规则把转化分配给广告或触点。
- **多触点归因：** 用模型分配多个触点的贡献，但结果依赖数据与模型假设。
- **增量测量：** 尽量回答“如果没有这项营销活动，结果会怎样？”

可用方法包括 A/B 测试、随机对照、地域/门店对照、留出组、前后对比结合对照，以及适用时的营销组合模型。选择方法时考虑预算、样本量、业务周期、可控性和数据质量。

### 17.3 复盘时回答六个问题

1. 原始业务问题是什么？
2. 哪个根因假设被证实、被否定或仍不确定？
3. 哪些触点完成了各自的任务？
4. 哪些结果可能是相关性，哪些有较强增量证据？
5. 预算、创意、渠道组合和执行中应继续、停止或调整什么？
6. 下一轮要做什么实验来减少最大的不确定性？

## 19. 项目启动检查清单

- [ ] 业务目标、基线、期限和约束明确；
- [ ] 已定位主要损失环节，而不是只描述总体表现不佳；
- [ ] 已使用消费者/市场证据检验根因假设；
- [ ] TA 基于需求、场景和行为，而不只是人口统计；
- [ ] Insight 有证据来源和置信度标记；
- [ ] KSP 转译成用户利益，并有可信 Proof；
- [ ] 已分析竞品、替代方案与“不购买”；
- [ ] 已明确要改变的认知、行为和业务结果；
- [ ] 每个渠道都有选择理由、主要任务和衡量方式；
- [ ] 渠道间的 CTA、信息和转化承接已打通；
- [ ] Ads、PR、Creator、EDM、Event 等专项计划有对应 Brief；
- [ ] 预算覆盖制作、授权、人员、跟进和测量成本；
- [ ] 日历、负责人、审批、依赖和风险明确；
- [ ] 已定义 Output、Outcome、Business KPI；
- [ ] 已区分平台归因与增量效果；
- [ ] 有复盘机制和下一轮实验计划。

## 20. 核心原则总结

**先用业务数据找到问题，再用用户证据解释问题；先定义需要改变的行为，再决定渠道组合；让每个触点承担明确任务，并用可验证的指标持续优化。**

IMC 不是“所有渠道都做”，而是让策略、内容、媒体、体验、转化承接和测量形成一套连贯系统。
